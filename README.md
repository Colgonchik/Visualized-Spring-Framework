# Visual SB — интерактивная лаборатория

Визуальный MVP для изучения Spring. Сайт воспроизводит проверенные Java-модули как управляемую модель: он не запускает JVM в браузере, но сохраняет порядок событий, условия и исходы из реальных примеров репозитория.

## Возможности MVP

Все 12 Java-модулей репозитория перенесены в 10 сцен:

- **01 · Запуск контейнера** (`#boot`): component scan, imports, properties, условия стартера и пользовательский бин.
- **02 · Путь HTTP-запроса** (`#request`): Security, аутентификация, DispatcherServlet, interceptor, контроллер, транзакция и БД.
- **03 · Жизненный цикл бина** (`#lifecycle`): instantiate → populate → init → BPP → готовый бин; ошибка init роняет контекст.
- **04 · AOP-прокси** (`#proxies`): JDK vs CGLIB, TransactionInterceptor, COMMIT/ROLLBACK и ловушка самовызова `this`.
- **05 · Условия создания бинов** (`#conditions`): @ConditionalOnProperty/OnClass/OnMissingBean и conditions report со счётчиком совпадений.
- **06 · Поиск компонентов** (`#scan`): базовый пакет, имена бинов и регекс-фильтр, отбрасывающий `excluded.*`.
- **07 · Метаданные бина** (`#definition`): программная регистрация BeanDefinition и lazyInit без единого объекта.
- **08 · Точки расширения BPP** (`#postprocessor`): before/after-обработка, JDK-прокси по @Logged и интерфейсу.
- **09 · Автоконфигурация молча** (`#autoconfig`): кандидаты из `*.imports`, фильтр по classpath и приоритет вашего `@Bean`.
- **10 · Чтение conditions report** (`#report`): `--debug`, positive/negativeMatches и сверка с `/actuator/beans`.
- **Свободная песочница:** узлы перетаскиваются, соединяются, переименовываются и удаляются; разорванный маршрут сообщает об ошибке; изменённый граф сохраняется в браузере.
- **Проигрыватель:** play/pause, шаг назад/вперёд (кнопки или стрелки ← →), скорость 1×–4× и журнал с переходом к предыдущему событию.
- **Два вида трассировки:** граф React Flow и диаграмма последовательности (UML sequence): линии жизни, сообщения-стрелки, будущие шаги приглушены, клик по сообщению перемещает проигрыватель.
- **Под капотом:** для каждого узла — роль, точка останова, связанный Java-модуль и фрагмент реального кода из репозитория.
- **Адаптивная раскладка:** десктоп и мобильный экран.

## Требования

- Node.js 22+ и npm 10+
- Для браузерных тестов — установленный Microsoft Edge

## Локальный запуск

Из корня репозитория:

```bash
cd site
npm install
npm run dev
```

Откройте `http://127.0.0.1:57321`. Десять сцен доступны сразу по адресам:

- `http://127.0.0.1:57321/#boot` — запуск контейнера
- `http://127.0.0.1:57321/#request` — путь HTTP-запроса
- `http://127.0.0.1:57321/#lifecycle` — жизненный цикл бина
- `http://127.0.0.1:57321/#proxies` — AOP-прокси и @Transactional
- `http://127.0.0.1:57321/#conditions` — условия создания бинов
- `http://127.0.0.1:57321/#scan` — поиск компонентов
- `http://127.0.0.1:57321/#definition` — метаданные бина
- `http://127.0.0.1:57321/#postprocessor` — точки расширения BPP
- `http://127.0.0.1:57321/#autoconfig` — автоконфигурация
- `http://127.0.0.1:57321/#report` — чтение conditions report

## Что проверить вручную

1. Запустите Boot и остановите сценарий на шаге условий.
2. Выключите `Автоконфигурация`: стартер отступит, финальный шаг покажет ошибку Runner.
3. Включите `Свой GreeterService`: появится пользовательский узел, а бин стартера будет пропущен.
4. В HTTP-сцене выключите credentials для `/private`: получится 401, контроллер не вызовется.
5. Переключите endpoint на `/public`: аутентификация не потребуется, получится 200.
6. Включите `Ошибка в сервисе`: после БД появится rollback и ответ 500.
7. В сцене 03 включите `Ошибка в init-методе`: init-этап упадёт, контекст не поднимется — как в Java-модуле.
8. В сцене 04 включите `Самовызов this.transfer()`: появится узел, который выполнится без своей транзакции (SKIP).
9. В сцене 05 выключите `Property включена`: FeatureService пропадёт, отчёт покажет negativeMatches.
10. Добавьте `Component`, соедините его с `Post-processors` и найдите его в журнале.
11. Выберите узел, измените название и удалите его кнопкой или клавишей Delete.
12. Проверьте мобильную ширину: панели располагаются друг под другом без горизонтального скролла.

## Проверка

```bash
npm test        # 31 unit-тест движка сценариев
npm run build   # production-сборка в site/dist
npm run test:e2e # 15 сценариев Playwright в Microsoft Edge
```

Playwright сам запускает Vite на `127.0.0.1:57321`. Конфигурация использует установленный Edge через `channel: 'msedge'`; скачивать Chromium не нужно.

## Структура

- `src/data/scenes.js` — начальные графы, настройки сцен и палитра.
- `src/data/code.js` — сниппеты реального Java-кода для инспектора (по узлам сцен).
- `src/lib/simulation.js` — порядок шагов, условия, ошибки и состояния узлов.
- `src/App.jsx` — сцены, проигрыватель, настройки и inspector.
- `src/components/Sandbox.jsx` — граф React Flow, соединения и drag-and-drop.
- `src/components/SequenceDiagram.jsx` — UML-диаграмма последовательности той же трассировки.
- `tests/engine.test.js` — unit-тесты сценариев.
- `tests/mvp.spec.js` — браузерные проверки пользовательских действий.

## Публикация

`npm run build` создаёт статический `dist/`. Параметр `base: './'` позволяет разместить сайт в подпапке, включая GitHub Pages.

## Ограничения MVP

- Все 12 Java-модулей покрыты сценами, но модель остаётся учебной: браузер не выполняет Java, а воспроизводит порядок событий, условия и исходы реальных примеров. Новая сцена добавляется декларативно в `src/data/scenes.js` (граф, настройки, условия видимости) плюс правила шагов в `src/lib/simulation.js`.
- Пользовательские узлы участвуют в учебной трассировке по типу; браузер не выполняет их как Java-классы.
- Для проверки настоящего поведения используйте команды `mvn spring-boot:run` и тесты соответствующих модулей.
