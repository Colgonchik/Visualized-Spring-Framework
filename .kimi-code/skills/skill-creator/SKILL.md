# Skill Creator

## Архитектура скилла

```
.kimi-code/skills/<имя>/
├── SKILL.md              # Точка входа: что умеет, когда использовать, навигация
└── references/           # Детали, подгружаемые по требованию
    ├── <тема>.md
    └── templates/        # Готовые шаблоны для копирования
```

Принцип: `SKILL.md` — короткий и навигационный; объёмные детали живут в `references/` и читаются только когда нужны.

## Правила содержимого

1. **Frontmatter обязателен**: `name` и `description` — без них скилл не распарсится. Опционально `whenToUse`.
2. **Язык — русский** (язык проекта), форматирование Markdown.
3. **Description** — одна строка, начинается с триггера («Используй когда...»): по ней модель решает, вызывать ли скилл.
4. **Ссылки на references** — относительные (`references/checklist.md`) и оформлены таблицей «когда читать».
5. **Один файл — одна тема**, до ~150 строк. Больше — разносить по references.
6. **Атрибуция**: если скилл адаптирован из чужого источника — ссылка и лицензия в первом блокquote.

## Создание нового скилла

1. Собери материал: реальные команды, выводы, точные имена классов. Не выдумывать.
2. Создай `.kimi-code/skills/<имя>/SKILL.md` по шаблону `references/templates/SKILL-template.md`.
3. Добавь references, если тело разрастается.
4. Проверь: имена и пути существуют, frontmatter валиден.
5. Прогони верификацию скиллом `verification`: скилл реально находится (`/skill:<имя>` в новой сессии), ссылки не битые.

## Улучшение существующего

- Тело > ~150 строк → вынести детали в references, в SKILL.md оставить навигацию.
- Устаревшее содержимое → сверить с текущим кодом проекта, переписать.
- Дублирование между скиллами → общее вынести в один reference, сослаться из обоих.

## Чек-лист

- [ ] Frontmatter: `name` совпадает с именем каталога, `description` есть
- [ ] Есть `whenToUse` — когда модель должна подхватить скилл сама
- [ ] Все пути из SKILL.md существуют на диске
- [ ] Файлы до ~150 строк
- [ ] Скилл вызывается: `/skill:<имя>` в новой сессии
