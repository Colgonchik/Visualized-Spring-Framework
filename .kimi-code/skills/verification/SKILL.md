# Верификация перед «готово»

## Идея

Сборка зелёная ≠ задача решена. Тесты проверяют код, верификация проверяет **исходный запрос**: правильное поведение, правильный вывод, отсутствие регрессий и побочных эффектов. Правило проекта: «не работает — не публикуем» относится и к документации: пример вывода в README должен совпадать с реальным.

## 6 шагов (обязательны перед словом «готово»)

**Шаг 1. Перечитай исходный запрос**
Вернись к исходному сообщению или задаче, прочитай слово в слово. Не опирайся на память.

**Шаг 2. Выпиши все критерии приёмки**
Явные и скрытые, пронумеруй. Если запрос расплывчатый — выпиши то, что разумно ожидал бы автор проекта. Правило, применённое к одной сущности (модулю, классу, формату вывода), проверь на всех её «сёстрах» — grep по аналогам.

**Шаг 3. Проверь каждый критерий доказательством**
Для каждого критерия — конкретное доказательство: вывод `mvn test`, реальный вывод `mvn spring-boot:run`, diff. «Должно работать» — не доказательство.

**Открой настоящий вывод (главное правило):** запусти реальную команду из README и сверь вывод с тем, что написан в README. Зелёные тесты ≠ готово: тест мог проверять не то, а пример вывода в документации мог устареть.

**Шаг 4. Проверь регрессии**
Прогони полный прогон из корня: `mvn test`. Сравни с состоянием до изменений. Новых падений и предупреждений быть не должно.

**Шаг 5. Проверь побочные эффекты**
Просмотри каждый изменённый файл (`git status`, `git diff`). Нет случайных правок не по делу? Конфиги и зависимости не тронуты без необходимости? Нет новых мусорных файлов (логи, `target/`, временные артефакты)?

**Шаг 6. Сформулируй вердикт с доказательствами**
В итоговом ответе: «выполнено» — только если у каждого критерия из шага 2 есть доказательство из шага 3, а шаги 4–5 чисты. Критерий без доказательства честно помечается «не проверено», а не сливается с «готово». Если что-то не удалось проверить — скажи об этом прямо.
