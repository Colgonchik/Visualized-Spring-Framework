# Типовые промахи в этом проекте

Частые причины «готово», которое оказывается не готово:

1. **README не сверен с реальным выводом.** Число bean definitions, имена бинов или форматирование в примере отличаются от того, что печатает приложение. Правило: пример вывода в README обновляется только по результату реального запуска.
2. **Тесты прогнаны только в модуле.** `mvn test` из папки модуля проходит, а из корня — нет (забыт `<module>` в корневом pom).
3. **Проверка «на глазок» вместо запуска.** Изменён `ScanReportRunner` или pom, но реальный `mvn spring-boot:run` не выполнялся — только компиляция.
4. **Мусор после прогона.** Логи, скачанные файлы, `*.jar` в корне — попали в `git status` и остались.
5. **Кодировка консоли.** Русский вывод приложения превращается в кракозябры при запуске через Git Bash без UTF-8 (см. `JAVA_TOOL_OPTIONS=-Dstdout.encoding=UTF-8`).
6. **Устаревшие формулировки.** После изменения поведения кода остались комментарии/разделы README, описывающие старое поведение.
7. **Косметический статус.** В корневой карте тем модуль помечен ✅, но тесты красные или модуль не запускается.
8. **Выдуманные детали в «Под капотом».** Номера строк исходников Spring, которые не сверялись с реально скачанными исходниками. Указывай класс и метод, номера строк — только после сверки.
