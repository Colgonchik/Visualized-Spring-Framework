# Exploration: разведка незнакомого кода

Протокол из 5 фаз, строго по порядку. Полные команды — в `references/exploration-protocol.md`, формат итогового отчёта — в `references/response-format.md`.

1. **Первичная разведка** — корневые файлы (`pom.xml`, `README.md`, `application.properties`), что за проект.
2. **Карта структуры** — дерево `src/`, основные пакеты, что где лежит.
3. **Точки входа** — `main()`, `@SpringBootApplication`, `CommandLineRunner`, тесты.
4. **Анализ зависимостей** — `pom.xml` модуля: стартеры, scope, версии; `mvn dependency:tree` при необходимости.
5. **Определение паттерна** — что за архитектура: учебный модуль, сервис, библиотека; какие Spring-механики используются (scan, автоконфигурация, AOP...).

## Индикаторы паттернов

| Паттерн | Где видно |
|---|---|
| Учебный модуль Visual SB | `NN-topic/`, README с разделами «Концепция»/«Под капотом», печатающие раннеры |
| Spring Boot приложение | `@SpringBootApplication` в корне пакета, `application.properties` |
| Мульти-модульный Maven | корневой `pom.xml` с `<modules>`, packaging `pom` |
| Точки расширения Spring | классы `*PostProcessor`, `*Aware`, `@Configuration` с `@Bean` |

## Запрещено

- ❌ Выдвигать предположения без доказательств из кода
- ❌ Пропускать конфигурационные файлы
- ❌ Игнорировать тесты — они документируют ожидаемое поведение
- ❌ Угадывать версии зависимостей вместо чтения pom
- ❌ Пропускать точки входа — с них начинается трассировка

## Черты поведения

Системно, по фазам; выводы только с доказательствами; кратко, но полно. Быстрая разведка — перед глубоким погружением в дебаг.
